# แผน OCR ภาษาไทย (ร่าง ยังไม่ใช่งานที่ทำแล้ว)

เขียนเมื่อ 2026-11-01 จากข้อมูลที่ค้นได้ในวันนั้น ตัวเลขทุกตัวมาจากหน้าของผู้สร้างโมเดลเอง ยังไม่มีใครวัดกับเอกสารไทยจริงของเรา

## ตอนนี้เป็นอย่างไร

OCR ในแอป (`crates/ocr`) ใช้เอนจิน `ocrs` กับโมเดลสองตัวที่ฝึกมาให้อ่านตัวอักษรละตินเท่านั้น รายการภาษาในโค้ดมีแค่ `English` ต้นทางเป็นแบบเดียวกัน ไม่ใช่เพราะเรา custom จึงอ่านไทยไม่ได้ทั้งสองฝั่ง

## ข้อกำหนดของเรา

- ใช้ได้ทั้ง Mac, Windows และ Ubuntu ด้วยโค้ดชุดเดียว ไม่ต้องให้ผู้ใช้ติดตั้งตัวรันโมเดลเพิ่ม
- โมเดลต้องมีใบอนุญาตเปิด ลงใน `ATTRIBUTION.toml` (`kind = "model"`) ตามนโยบายสินทรัพย์ของต้นทาง (AGENTS.md ข้อ 1)
- ต้องได้ตำแหน่งของแต่ละบรรทัด เพราะงานที่เราอยากทำคือแก้ข้อความที่ฝังในภาพ ต้องรู้ว่าจะลบพิกเซลตรงไหนแล้ววางข้อความใหม่ที่ไหน

## ถ้าใช้โมเดลใหญ่ทีเดียว จะจบไหม

ไม่จบครับ ขนาดไม่ใช่คอขวด:

- **ไม่มีพิกัด:** โมเดลภาษา-ภาพ (Typhoon, Xiaomi) ตอบเป็นข้อความ ยังต้องมีตัวตรวจบรรทัดแยก แล้วอ่านทีละบรรทัด งานตรวจบรรทัดก็คือตัวเล็กแบบ Paddle อยู่ดี
- **อ่านผิดแบบแต่งขึ้น:** หน้าของทั้งสองบอกเองว่าอาจแต่งข้อความ ถ้าใช้กับชื่อบนใบประกาศ ต้องมีคนตรวจทุกครั้ง
- **หนักและช้ากว่า:** ต้องมีตัวรันโมเดลเพิ่ม (vLLM, Ollama, llama.cpp) หรือ GPU และไฟล์ระดับ GB
- **งานที่เหลือเหมือนกันทุกทาง:** ลบพิกเซลเดิม วางข้อความใหม่ด้วยฟอนต์ไทย ผูกเข้ากับเครื่องมือ Edit Text ซึ่งเราลองทำเป็นต้นแบบแล้ว (Apple Vision, เติมสีเรียบ, Add Text)

## แผน

0. **รอและตามต้นทาง** issue #1601 และ #3326, PR #2520 และ #4659 ใน `storytold/pdfcraft` เมื่อโครงรองรับหลายภาษาถูก merge เข้ามา ให้ซิงก์ตามขั้นตอนใน `CUSTOM.md`
1. **ทดลองนอกแอป:** รัน PaddleOCR ไทย (ตัวตรวจ + ตัวอ่าน) กับใบประกาศใบเดิม วัดตัวไทยที่อ่านผิด เวลา และหน่วยความจำ เทียบกับ Apple Vision ชุดเดียวกัน เกณฑ์ผ่าน: ไม่แย่กว่า Apple Vision อย่างเห็นได้ชัด
2. **เติมโมเดลไทยเข้ากรอบของต้นทาง:** เพิ่มไฟล์โมเดลและพจนานุกรมไทยลง `ATTRIBUTION.toml` ไม่เขียนระบบอ่านเอง
3. **ถ้าจำเป็น:** ตัวช่วยตรวจคำด้วยโมเดลภาษา เป็นตัวเลือกที่ผู้ใช้เปิดเอง และต้องมีคนตรวจก่อนบันทึกเสมอ
